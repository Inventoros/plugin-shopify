# Inventoros Official plugin matrix

All 31 planned plugins, in build order. Every plugin is its own repository, `Inventoros/plugin-{slug}`, created private; the free ones are flipped public after review. Gap IDs (G1 to G18) refer to [SDK-GAPS.md](SDK-GAPS.md); conventions (prefixes, kit, licensing) to [CONVENTIONS.md](CONVENTIONS.md).

Core v2.0 already ships, and no plugin re-implements: stock audits with scheduled cycle counts and approvals; BOMs (kit and assembly product types with derived kit availability) and work orders; batches with FEFO allocation; serials; per-location bins (aisle, shelf, bin, capacity); warehouses with user access; the reorder service, per-warehouse reorder points and quick reorder; dead-stock, turnover, margin and ABC reports plus a report builder; shipping with EasyPost labels and tracking; a customer portal (orders, invoices, returns); payments and discounts; CSV import and export of products, orders and users; barcode and QR generation, a scanner modal and scan lookup; outbound webhooks with delivery logs; REST, GraphQL and an MCP server.

## Principles behind the matrix

- **No hard plugin-to-plugin dependencies.** Every plugin installs on core alone. Where two plugins are better together (Forecasting feeding Replenishment, Pick Path ordering Wave Picking's lists, Barcode scanning in Packing Station), the provider fires a namespaced hook (`do_action` / `apply_filters('{slug}_...')`) and the consumer uses it when present and degrades when absent. Core has no `depends` and does not need one (G17).
- **Build on core records.** A cycle count is a core stock audit, a pick confirmation moves stock through core services, an imported order is a core order. Plugin tables hold only what core has no place for (configuration, mappings, plans, ledgers, history).
- **Integrations share one design, not one plugin.** Shopify, WooCommerce, Amazon, ShipStation, QuickBooks and Xero each carry a namespaced copy of the integration kit (connections, encrypted credentials, sync runs and logs, retry and rate limiting, webhook inbox, mappings).

## Where a plugin overlaps core, and what it is for

| Plugin | Core already does | The plugin's distinct value |
|--------|-------------------|-----------------------------|
| CSV Import/Export | Products, orders, users import and export | The other entities, mappings, preview, history, schedules |
| Barcode | Code generation, a scanner modal on some screens, scan lookup | A complete scanning workflow for warehouse staff |
| Basic Cycle Counts | Audits, schedules, approvals | Who counts what, blind counts, recounts, reason codes |
| Advanced Cycle Counts | Schedules that create draft audits | Deciding what to count and when, and measuring accuracy |
| Webhooks+ | Signed webhooks, delivery logs | Filtering, shaping, replaying, plugin events |
| ShipStation | EasyPost labels and tracking | Working inside an existing ShipStation operation |
| Inventory Insights | Dead stock, turnover, margin, ABC reports | Explanations and recommended actions, ranked |
| Advanced Replenishment | Reorder points, suggested quantities, quick reorder | Safety stock, lead-time variability, packs, tiers, explanations |
| Expiry / FEFO | Batches, expiry dates, FEFO allocation | Quarantine, recalls, traceability, expiry alerts |
| Kitting / Bundles | Kit and assembly types, derived kit availability | Physical builds and breakdowns, substitutes, channel availability |
| Manufacturing | Single-level BOM, work orders | Multi-level, routings, planning, scrap, costing |
| Multi-Company | Strict per-organization tenancy | Controlled movement and reporting across organizations |

## Recommended build order

The owner's order holds, with Webhooks+ after Teams and the warehouse group ordered by its internal dependencies:

| Step | Plugins | Core work that must land first |
|------|---------|--------------------------------|
| 0 | Conventions, template (done) | G1, G2 (phase 1 core PR) |
| 1 to 3 | CSV Import/Export, Barcode, Basic Cycle Counts | none beyond G1, G2; a stock-audits slot (G6) is optional |
| 4 to 6 | Shopify, WooCommerce, ShipStation | G3 (or ship with model events), integration kit v1 extracted from Shopify |
| 7 to 9 | Slack, Teams, Webhooks+ | G9 before Webhooks+; an approval-requested hook (G3 family) |
| 10 | Amazon | G4 decision for FBA |
| 11 to 15 | Insights, Health Pro, Advanced Replenishment, Forecasting, AI Assistant | G7 before Insights (first paid plugin); G10 before AI Assistant |
| 16 to 21 | Warehouse Map, Putaway, Pick Path, Wave Picking, Packing Station Pro, Advanced Cycle Counts | G6 slots per page; G4 before Wave Picking |
| 22 to 23 | QuickBooks Online, Xero | none new |
| 24 to 28 | Expiry/FEFO, Kitting, Rental, Asset Management, Consignment | G4 before Expiry quarantine and Rental |
| 29 | Multi-Company | Organization membership and switching in core (separate design) |
| 30 | 3PL Management | G16, G11 design |
| 31 | Manufacturing | none new beyond G4 |

Size key: S under a day, M one to two days, L three to five days, XL more than a week of focused work, each including tests, docs and CI. The owner's one-plugin-per-hour pace fits a scaffold with one working vertical slice per plugin; L and XL plugins need further passes to meet their full brief.
